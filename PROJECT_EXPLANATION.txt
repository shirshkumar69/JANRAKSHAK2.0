1. EXECUTIVE SUMMARY & WHAT THE PROJECT IS
--------------------------------------------------------------------------------
JANRAKSHAK is an enterprise-grade, real-time "Command Center" for predicting multi-
hazard landslides anywhere on Earth. Originally built for the Himalayan NH-07
highway corridor, the system is now a Global Geotechnical Intelligence Platform.

It doesn't just look at rainfall; it actually calculates the physical probability

live weather, live earthquakes, and 3D terrain into one unified operational dashboard.

2. CAN JANRAKSHAK ACTUALLY PREDICT LANDSLIDES? (SCIENTIFIC REALITY & ACCURACY)
--------------------------------------------------------------------------------
YES — as a dynamic, physics-based regional early warning and susceptibility system.

JANRAKSHAK accurately determines WHICH mountain slopes and highway corridors are
reaching their physical breaking point under real-time rainfall saturation and
earthquake acceleration.

What it predicts:
* Geotechnical Failure Probability: When resisting forces fall below driving forces
  (Factor of Safety FoS < 1.00).
* Lead Time: Identifies critical stress build-up hours before collapse occurs,
  giving NDMA/USDMA authorities actionable time to close roads, divert traffic,
  and evacuate toe settlements.
* What it does NOT claim: No software or satellite model can predict the exact
  micro-second a specific rock falls down to the millimeter. It predicts regional
  and slope-scale failure conditions.

Why JANRAKSHAK's Physics Approach Beats Standard Apps:
1. Conventional Systems Fail: Most weather tools just use simple rain thresholds
   (e.g., "Alert if rain > 50mm"). But 50mm rain on a flat 10° plain causes puddles;
   the exact same 50mm rain on a 38° steep colluvial slope causes a deadly debris flow.
2. Mohr-Coulomb Effective Stress: JANRAKSHAK calculates the live balance between
   shear strength (cohesion c' + friction phi') and gravitational driving forces.
3. Green-Ampt Hydrological Pore Pressure: It models subsurface water pressure (u)
   pushing soil grains apart from the inside, reducing effective stress (sigma' = sigma - u).
4. Compound Multi-Hazard: It catches compound events where moderate rain + a small
   earthquake (kh = 0.08g) causes a catastrophic failure that neither would cause alone.

The 3 Tiers of Disaster Early Warning (Where JANRAKSHAK Fits):
* Tier 1: Static Susceptibility Maps (Old government paper maps — never update).
* Tier 2: Dynamic Physics & Satellite Early Warning  ◄── [ JANRAKSHAK'S ROLE ]
  (Live Doppler radar, NASA DEM slope angles, Green-Ampt pore pressure, USGS quakes,
   real-time FoS across 50+ corridors and global coordinates).
* Tier 3: In-Situ IoT Hardware Sensors ($50,000+ per slope drilled into single rocks).

Real-World Limitations & How to Answer Judges Scientifically:
* Topography: NASA SRTM is 30m resolution. Next-phase upgrade: High-res UAV drone LiDAR (0.5m).
* Subsurface Soil: Calibrated to GSI/BIS geological lithologies. Next-phase upgrade: Local borehole ERT data.

3. HOW WE GET LIVE DATA FOR FREE (THE ZERO-KEY ARCHITECTURE)
--------------------------------------------------------------------------------
Most real-time weather/seismic systems cost thousands of dollars per month. We
engineered JANRAKSHAK to use "Zero API Keys". We pull open-source data bypassing
all paywalls:

* PRECIPITATION & WEATHER: We use the Open-Meteo API. It provides non-commercial
  real-time weather, 24-hour antecedent rainfall, rain rates, surface pressure,
  and temperature without any key.
* DOPPLER WEATHER RADAR: We tapped directly into the public `RainViewer` tile cache
  (https://tilecache.rainviewer.com). This provides moving radar clouds and storm
  cells without needing a paid mapbox or radar API.
* EARTHQUAKES & SEISMICITY: We use the USGS (United States Geological Survey)
  GeoJSON Live Feed. Our Python backend polls this every minute to find global
  earthquakes, dynamically calculating ground shaking intensity.
* ELEVATION & TOPOGRAPHY: We use NASA's SRTM 30m (Space Shuttle Radar Topography
  Mission) Digital Elevation Model via Open-Meteo. Give it a coordinate, and it
  returns the altitude in meters.
* MAPS (GIS): OpenStreetMap, CartoDB Dark Matter, and OpenTopoMap for the base maps.

4. HOW THE PHYSICS ENGINE DETECTS LANDSLIDES (THE MATH)
--------------------------------------------------------------------------------
This is the heart of the project. We calculate the "Factor of Safety" (FoS).
FoS is a ratio: How strong the dirt/rock is (Resisting Force) DIVIDED BY how much
gravity and earthquakes are pulling it down (Driving Force).
If FoS > 1.30, the mountain is STABLE (Green).
If FoS is between 1.00 and 1.30, it is MARGINAL (Yellow, Warning).
If FoS < 1.00, the mountain is collapsing: UNSTABLE (Red, Critical).

The 3 Equations in our Python Backend (app.py):
1. Mohr-Coulomb Failure Criterion: Dictates soil shear strength based on Cohesion
   (stickiness of mud) and Friction Angle (roughness of rocks).
2. Green-Ampt Hydrological Infiltration: Tells us how much rain actually soaked
   into the ground and turned into Pore Water Pressure (which blows apart the soil).
3. Pseudo-Static Seismic Force (Kh): If an earthquake happens nearby, we add a
   horizontal "kick" (gravity modifier) pulling the slope sideways.

6. HOW WE FIXED THE TECHNICAL BUGS & SECRETS OF THE BUILD
--------------------------------------------------------------------------------
If asked how you built this or solved problems, tell them:

* The Map SVG Click Bug: At first, the "Red Pulsing Rings" on our map intercepted
  mouse clicks, preventing users from clicking the actual location markers to read
  the data. We solved this by creating the pulse ring as a separate `L.circleMarker`
  with `{ interactive: false }` and `pointer-events: none`, allowing clicks to pass
  through the animation down to the data pin.
* API Key Bypass: We didn't want the project to die when a trial API key expired
  during presentation. So we wrote Python wrapper scripts (`get_radar_data`,
  `get_realtime_weather`) that hit open government/scientific endpoints (Open-Meteo,
  USGS) which do not require HTTP Bearer Tokens.
* Multithreading vs WebSockets: We used Python threading (`async_mode='threading'`)
  in our background telemetry loop so that pulling weather data for 50 cities
  doesn't freeze the Flask web server. The data is kept in a global Python dictionary
  (`system_state`) and broadcasted safely via `socketio.emit()`.
* High-Altitude Pressure Altimetry: High mountain peaks in Garhwal lack ground barometers.
  We implemented standard barometric altimetry formulas ($1013.25 - \text{elev}/8.3$)
  for seamless atmospheric pressure fallback.
